# ТЗ: прогон R3.1. Сеть Phase 3 с ODE-членом и без него

## 0. Кратко

Обучи сеть Phase 3 дважды на одной и той же траектории: с ODE-членом в loss (конфигурация A) и без него (конфигурация B). Всё остальное оставь одинаковым. Сравни результаты на 10 сидах в двух кейсах. Верни таблицы, рисунки и короткий отчёт. Ничего не подбирай и не настраивай.

## 1. Цель и контекст

Рукопись: MDPI *Viruses*, viruses-4607077, версия от 26 октября 2026. Метод: трёхфазный. Phase 3 — сеть с мягким штрафом по ODE. Сеть обучается на принятой симуляции из Phase 2.

Рецензент 3, замечание 1. Рецензент пишет: ни один эксперимент не показывает, что PINN лучше обычной MLP. Он просит минимум один эксперимент: PINN против такой же MLP без ODE-члена, на тех же данных и в том же окне.

Что нужно от этого прогона: честное сравнение A и B. Результат даст одно предложение в ответе рецензенту. Статус «physics-informed» в Abstract и Conclusions понижается при любом результате. Поэтому не ищи «выгодный» исход. Сообщай то, что получилось.

## 4. Конфигурации

- **A (PINN).** Loss = λ_data·L_data + λ_ode·L_ode + λ_ic·L_ic, λ_ode = 0.1. Это конфигурация рукописи.
- **B (MLP).** Тот же loss, но λ_ode = 0. Никакие другие изменения не допускаются.

Для B вычисляй значение L_ode только для журнала. Не добавляй его в loss. Не пропускай через него градиент.

Правила «одинаково»:
1. Одинаковые данные, окно 0–400, архитектура, оптимизатор, число эпох.
2. Для одного сида начальные веса A и B должны совпадать. Задай `torch.manual_seed(seed)` непосредственно перед созданием модели. Проверь хэшем весов (раздел 8, проверка S3).
3. Scheduler остаётся как в коде. Он смотрит на общий loss. У B общий loss другой. Это допустимое следствие, а не ошибка. Запиши это в отчёт.

## 7. Метрики

Обозначения. `y_sim` — принятая симуляция (цель обучения). `y_net` — выход сети. Компартменты: S, I, R, D. Сетка обучения — 1 000 точек (дни 0–400). Все ошибки — со знаком, если не сказано иное. Правая часть ODE `f(y; β, γ, µ)` — та же функция, что в loss кода.

### 7.1. Режим «dropout выключен» (детерминированный проход)

| Код | Определение |
|---|---|
| `peak_h_err_pct` | 100·(max I_net − max I_sim) / max I_sim |
| `peak_day_err` | день максимума I_net − день максимума I_sim (дни) |
| `rmse_I` | RMSE между I_net и I_sim на сетке обучения |
| `relrmse_k` | RMSE_k / max(y_sim,k), для k = S, I, R, D |
| `odeRes_k` | RMS по времени от (dy_net,k/dt − f_k(y_net)), делённое на RMS по времени от f_k(y_sim). Сетка: 4 000 равномерных точек на 0–400. Производная — по времени в днях, через autograd |
| `dI_err` | RMS по времени от (dI_net/dt − f_I(y_sim)), делённое на RMS от f_I(y_sim). Та же сетка 4 000 точек. y_sim на этой сетке — от решателя ODE |

Для `odeRes_k` и `dI_err` пересчитай производную в дни. Если код использует нормированное время или масштабированные выходы, учти цепное правило.

### 7.2. Режим «dropout включён» (100 проходов, p = 0.005)

Используй код полосы из скрипта Phase 3 без изменений. Включая сглаживание краёв, если оно там есть.

| Код | Определение |
|---|---|
| `mean_peak_h_err_pct` | как `peak_h_err_pct`, но для среднего по 100 проходам |
| `mean_peak_day_err` | как `peak_day_err`, но для среднего |
| `sim_peak_in_band` | да/нет: лежит ли I_sim в день его максимума внутри полосы 2.5–97.5 % |
| `band_w_pct` | 100·(верх − низ) / максимум среднего, в день максимума среднего |

Определения `sim_peak_in_band` и `band_w_pct` должны совпадать с Appendix E.3 рукописи. Сверь с кодом. Если код считает иначе — запиши, как именно.

### 7.3. Сводка по сидам

Для каждой пары «кейс × конфигурация» и каждой метрики: среднее, SD, медиана, min, max по 10 сидам.

Парное сравнение (тот же сид): разность B − A для каждой метрики; среднее и SD разности; число сидов из 10, в которых A лучше B (по модулю ошибки; для `odeRes_k`, `dI_err`, `relrmse_k`, `rmse_I` — по значению). Тесты значимости не нужны.

Флаги (считай автоматически, без интерпретации):
- `range_overlap_peak_h`: пересекаются ли диапазоны [min, max] от |`peak_h_err_pct`| у A и B (да/нет).
- `range_overlap_relrmse_I`: то же для `relrmse_I`.
- `A_lower_odeRes`: у A `odeRes_k` ниже, чем у B, в скольких сидах из 10.
